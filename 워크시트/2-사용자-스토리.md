## 사용자 스토리가 뭔가요?

사용자가 우리 서비스를 **실제로 사용하는 장면**을 미리 글로 그려보는 거예요.
이걸 써 두면 좋은 점이 세 가지 있습니다.

1. 만들어야 할 기능이 무엇인지 분명해져요.
2. "스토리 하나 완성 = 사용자가 써볼 수 있는 기능 하나 완성"이라서 진행 상황을 세기 쉬워요.
3. 나중에 화면 설계, 시스템 설계를 할 때 그대로 재료가 됩니다.

## 1. 우리 서비스의 사용자는 누구인가요? (페르소나)

## 2. 사용자 스토리 작성

한 스토리는 두 부분으로 씁니다.

- **한 줄 스토리:** `〈누구〉로서, 〈하고 싶은 것〉을 원한다. 왜냐하면 〈이유〉 때문이다.`
- **시나리오 (Given/When/Then):** 그 기능이 실제로 돌아가는 장면 하나
  - **Given(주어진 상황):** 어떤 상태에서
  - **When(행동):** 사용자가 무엇을 하면
  - **Then(결과):** 무슨 일이 일어난다

### 완성 예시 — 교내 분실물 찾기 앱 "어디놨지"

> **한 줄 스토리:** 물건을 잃어버린 학생으로서, 내 물건이 접수됐는지 검색하고 싶다. 왜냐하면 분실물함을 층마다 돌아다니지 않고 바로 찾고 싶기 때문이다.
>
> **시나리오:**
> - Given: 누군가 주운 체육복이 앱에 사진과 함께 등록되어 있다
> - When: 지우가 검색창에 "체육복"을 입력한다
> - Then: 등록된 체육복 목록이 사진과 보관 장소와 함께 표시된다

## 3. 셀프 체크리스트

- [ ] 스토리마다 "왜냐하면"에 진짜 이유가 있다 (기능 설명 반복이 아니라)
- [ ] Then(결과)이 눈으로 확인 가능하다 — 화면에 뭐가 보이는지, 뭐가 바뀌는지
- [ ] "꼭 필요" 스토리만으로도 서비스의 핵심이 돌아간다
- [ ] 스토리 하나가 너무 크지 않다 (한 번의 사용 장면 하나만 담기)
